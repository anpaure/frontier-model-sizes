# Forecast pipeline

`sources/human_parameter_forecasts_2026-07-17.csv` is the single editable source for human parameter forecasts. The date is the durable ledger's creation date; later revisions append to the same file. Each row is one anonymous respondent/model forecast. Ranges are stored as `low_t` and `high_t`; `central_t` preserves a separately stated central estimate. When `central_t` is blank, the pipeline uses the geometric midpoint of the range. Point forecasts set all three fields to the same value. Revisions append a new row and name the prior opaque `forecast_id` in `supersedes`. Stable `Respondent RNN` IDs preserve cross-target pairing, while the repository stores no respondent names or reverse mapping.

Run:

```bash
./run_forecast_pipeline.py
```

This regenerates the DOCX registry, XLSX forecast workbook, and the website's normalized JSON data contract. It recalculates active respondent counts and equal-weight geometric crowd centers, reproduces aggregate ECI from the pinned official Epoch implementation, updates the 50/50 log-space ensemble and chart, rebuilds the interactive website, and runs the forecast-consistency, unified-data, ECI-reproduction, first-party-frontier, Artificial Analysis parameter/inference/operational, active-parameter transport, OpenRouter, ECI-component, post-training-lineage, IKP, poll-privacy, independent-reproduction, and rendered-site suites.

Its public derivative replaces poll identities only, cryptographically cites the original artifact, and proves that crowd points, centers, weights, forecasts, and intervals are unchanged. The name-bearing original bytes and reverse mapping are not retained in the current tree. The recurring pipeline intentionally never invokes the one-shot freeze builder. After all statistical stages complete, `generate_model_readiness_report.py` regenerates [`MODEL_READINESS.md`](MODEL_READINESS.md) and its hashed JSON contract before the final independent reaudit and presentation checks.
